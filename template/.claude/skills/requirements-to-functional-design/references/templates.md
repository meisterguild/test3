# 設計書テンプレート

各ファイルのテンプレートと記載項目の定義。`<>` はプレースホルダ。見出し構成は変えずに使う（実装エージェントが機械的にセクションを特定できるようにするため）。案件に存在しない小項目は「該当なし」と書いてよいが、見出し自体は残す。図は Mermaid で埋め込む。

## 共通ルール

- 各設計項目には、根拠となる要件 ID を `（根拠: R-01, R-02）` の形で付ける。要件 ID は入力資料に採番があればそれをそのまま使い（`FN-01` など形式は問わない）、仮 ID（R-01 形式）はスキルが採番した項目にだけ使う。テンプレート中の `R-xx` は要件 ID のプレースホルダであり、R 形式への振り直しを求めるものではない。
- 要件に根拠がなく、承認済み設計判断に由来する項目は `（根拠: D-01）` のように判断 ID を付ける。
- どちらにも根拠を書けない記述は創作の疑いがある。書く前に立ち止まって質問に戻る。
- 改定時、既存の要件 ID・判断 ID・質問 ID は変更しない。追加分は連番の続きで採番し、欠番が生じても再利用しない（改訂履歴やレビュー記録から旧 ID が参照されているため）。
- 削除された要件は要件対応表から行を消さず、「対応する設計」欄に `廃止（v1.1）` のように廃止時の版を記す。
- セクションを分割した場合（SKILL.md「規模に応じた分割」）、一覧系の見出し（エンドポイント一覧・画面一覧など）は `00-index.md` に、個別定義の見出しは各分割ファイルに置く。見出しの構成自体は変えない。

## 00-overview.md

```markdown
# <システム/機能名> 基本設計書

<何を作るかの要約。2〜3文>

## 改訂履歴

<初版は 1.0。改定モードでの更新ごとに 1.1、1.2 と進め、全再生成した場合は 2.0 のようにメジャーを上げる。日付は実行環境から取得した当日の日付を使う>

| 版  | 日付         | 改訂内容         | 契機                        | 更新ファイル  |
| --- | ------------ | ---------------- | --------------------------- | ------------- |
| 1.0 | <YYYY-MM-DD> | 初版             | —                           | 全ファイル    |
| 1.1 | <YYYY-MM-DD> | <変更内容の要約> | <R-xx 変更、R-yy 追加 など> | <02, 03 など> |

## 入力情報

- 入力資料: <パスまたは URL。複数あれば種別（要件定義書 / Figma デザイン等）を添えて列挙する>
- 対象: <新規システム / 既存システム（リポジトリ名）への機能追加>

## 読む順序

<セクションを分割している場合は、ディレクトリ名ではなく分割後の実ファイル単位（03-api/01-auth.md など）で行を設ける>

| ファイル           | 内容                               | 読むべき場面                 |
| ------------------ | ---------------------------------- | ---------------------------- |
| 01-architecture.md | アーキテクチャ・コンポーネント分割 | 最初に全員                   |
| 02-data-model.md   | データ入出力・データモデル・DB設計 | データ操作を実装するとき     |
| 03-api.md          | API・外部インターフェース設計      | エンドポイントを実装するとき |
| 04-ui.md           | 画面設計                           | UI を実装するとき            |

## 設計判断サマリ

<承認済みの設計判断。レビュアーが創作判定の根拠に使うため、質疑応答で決まったことも漏らさず書く>

| ID   | 判断         | 採用案   | 却下案と理由           | 承認 |
| ---- | ------------ | -------- | ---------------------- | ---- |
| D-01 | <判断の内容> | <採用案> | <却下した選択肢と理由> | 済   |

### 質疑応答の記録

| ID   | 質問（要件の穴）     | ユーザーの回答 |
| ---- | -------------------- | -------------- |
| Q-01 | <何が不足していたか> | <回答>         |

## 省略したセクション

<なし、または「04-ui.md — 本件は CLI ツールであり UI を持たないため（D-02 で承認済み）」の形式>

## 要件対応表

<すべての要件 ID を列挙する。設計しない要件（スコープ外など）も理由付きで残す>

| 要件 ID | 要件の要約 | 対応する設計                       |
| ------- | ---------- | ---------------------------------- |
| R-01    | <要約>     | 02-data-model.md の <セクション名> |
| R-02    | <要約>     | 対象外（<理由>）                   |
```
