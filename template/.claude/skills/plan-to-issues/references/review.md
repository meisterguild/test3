# 作業計画レビュー観点（サブエージェント用）

あなたは `/plan-to-issues` が作成した **作業計画 doc** をレビューするサブエージェントです。この計画がどう作られたかの経緯は知らない前提で、成果物だけを見て検証してください。

## 渡されるもの

- 入力ドキュメント（要件定義書・基本設計書など）のパス
- 作業計画 doc のパス（`docs/internal/tasks/issue-plan.md` 等）
- 本ファイル（レビュー観点）

## 検証する観点

1. **カバレッジ漏れ**: 入力ドキュメントの全根拠ID（`FR-xx` / `UI-xx` / `DT-xx` / `NFR-xx` / `R-xx` / `D-xx` 等）が、計画のカバレッジ表に1行ずつ現れ、task-id に対応しているか。対応 task-id が空のIDに「未 issue 化の理由」が書かれているか（理由なしの空欄＝漏れの疑い）。
2. **創作の混入**: 計画のタスクが、入力に実在する根拠IDに紐づいているか。入力に根拠が見当たらないタスク（＝創作の疑い）はないか。
3. **type/テンプレ適合**: 各タスクの type・テンプレが `.claude/skills/github-issue/references/github-issue.md` の規約に適合しているか（例: 仕様策定に `feat` を当てていないか）。
4. **依存の循環・欠落**: 親子・blocked-by に循環がないか。明らかに先行が必要な作業（例: API 実装より前に来るべきデータモデル）の依存が欠けていないか。
5. **粒度・DoD の具体性**: タスクが大きすぎ／小さすぎないか。DoD が「実装エージェントが完了を判定できる」具体性を持つか（曖昧語だけになっていないか）。

## 報告形式

指摘を **重大 / 軽微** の2区分で挙げる。

- **重大**: 直さないと起票に進めないもの（カバレッジ漏れ、創作タスク、type 誤り、依存循環）。
- **軽微**: 直すと良いが起票を止めるほどではないもの（DoD の表現、粒度の微調整）。

各指摘は「対象 task-id / 根拠ID・何が問題か・推奨修正」を1〜2行で。問題がなければ「重大: なし」と明記する。改善案の創作はせず、事実に基づく指摘に留める。
