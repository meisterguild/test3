# デザインルール（rules/）

このフォルダは、AI エージェントが要件から Figma デザインを作るときに従う**共通ルール集（汎用）**です。すべての案件で使い回します。案件ごとの個別の値や決定は、ここではなく成果物フォルダ（`docs/internal/design/`）側に書きます。

## 一番大事な考え方

> Figma は「完成物」ではなく、**AI と人間が往復で使う中間成果物**として扱う。だから「AI が後から読み直しても、構造・責務を推測しなくてよい状態」を最優先にする。「AI が作りやすい」より「AI が読み直しやすい」を優先する。

最終的な品質判断（違和感・余白感・業務妥当性・ブランド品質）は**人間が行う**。AI は生成・整理・自己レビュー・修正を担当する。

## どこに何を書くか（Figma 注釈 と md の分担）

「どこに書くか」を AI が迷わないよう、責務を分ける。

- **Figma（Annotation）**：その画面・要素の**局所的な情報**を最小限に書く（使い方 / Variant の使い分け / Interaction / Responsive / 実装メモ など）。Dev Mode 向けの補助。
- **md**：**横断する規則・設計**を書く（Design Rule / Token / Naming / Component / 全体仕様）。汎用ルールはこのフォルダ（`rules/`）、案件固有の値・決定は `docs/internal/design/`。
- 原則：Figma 内のドキュメントは最小限にし、規則・全体仕様は md に集約する。**Design Rule（汎用）と画面仕様（案件固有）を混ぜない。**

## ファイル一覧

Figma 制作・デザイン判断・レビューのときは、このフォルダ（`rules/`）配下の各ファイルを「**現行デザインルール（design rules）＝正本**」として参照する。単一の `FIGMA.md` は設けず、観点ごとに下表のファイルへ分割して管理する（下表が参照入口）。

| ファイル                  | 役割                                                                |
| ------------------------- | ------------------------------------------------------------------- |
| naming-conventions.md     | 名前の付け方（Layer / Component / Variable / Style …）              |
| tokens-and-scales.md      | 色・余白・文字サイズなどの値とスケール                              |
| structure.md              | 構造（Auto Layout / レイヤー責務 / Component）                      |
| quality.md                | 品質・アンチパターン・アクセシビリティ                              |
| self-review.md            | AI の自己レビュー観点                                               |
| wireframe.md              | ワイヤーフレームの作り方（凡例・キャプション・状態・分割）          |
| ui-ux-principles.md       | UI/UX 操作性の普遍原則（タップ領域・必須明示・エラー位置 等）       |
| patterns.md               | 状況別デザイン解決の辞書（削除・必須・エラー・空状態・モーダル 等） |
| handoff.md                | 完成前の整理と FE 引き渡し                                          |
| design-readiness-check.md | 要件がデザインに進める状態かの着手チェック                          |
| external-review-guide.md  | 外部レビュアー（別 AI・人間）への依頼観点                           |

## デザインフェーズの流れ

```text
要件定義 md（入力）
  ↓
① 着手チェック（design-readiness-check.md）  → ★CP1 人間 / PM 確認
  ↓
② 画面整理（画面一覧・画面定義・簡易フロー）
  ↓
③ ワイヤーフレーム（Figma WF → 別エージェントで自己レビュー）  → ★CP2 人間確認
  ↓
④ デザイン（Figma → 別エージェントで自己レビュー ＋ 外部レビュー）  → ★CP3 人間 / FE 確認
  ↓
⑤ FE 引き渡し整理（handoff.md）
```

★＝人間の確認ポイント。承認なしに次へ進まない。

## 役割分担

| 担い手                        | 役割                                                     |
| ----------------------------- | -------------------------------------------------------- |
| メインのエージェント          | 制作・修正                                               |
| レビュー用エージェント        | 自己レビュー＝監査（self-review.md。メインとは別に起動） |
| 外部レビュアー（別 AI・人間） | デザイン・構造レビュー（external-review-guide.md）       |
| Figma                         | 可視化・実装接続の中間成果物                             |
| 人間                          | 違和感・業務妥当性・最終品質の判断                       |
