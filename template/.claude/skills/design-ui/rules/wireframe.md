# Wireframe（ワイヤーフレーム）ガイド

ワイヤーフレーム工程の作り方をまとめる。色を当てる前に情報構造・導線を固め、AI が仕様を推測しないための「情報固定レイヤー」を作る。WF はデザインの使い捨てではなく、トークンを当てて 02_Design へ**昇格**させる土台。

## 網羅性（必要な画面・状態をすべて作る）

WF は「どんな画面・機能があるか」をビジュアルで一覧確認するための成果物。仕様を可視化し、実装・レビューの基準になるため、**網羅性を品質の前提**とする。

- 要件にある画面・状態・機能は**原則すべて画面化**する。省略してよいのは「同一画面でメッセージだけが違うバリデーション」など**純粋な重複のみ**（重複は代表1枚で表す）。
- 要件に明記が無い画面・状態も、**UX 観点で必要なものは能動的に洗い出して補う**（迷ったら作る）。
- 洗い出しは次の**状態カテゴリ**で総点検する（取りこぼし防止）：
  1. 各ドロップダウン／セレクトの**展開状態**
  2. 非同期処理の**「取得中（ローディング）」と「失敗（エラー）」**
  3. 表示データが**空・任意項目が未入力**のときの表示
  4. **通知・トースト・バナー**（保存完了・警告など）
  5. **OS 権限・OS 機能有効化は OS 標準に委譲**し画面化しない（アプリ内のロール権限差分とは別物。ロール権限差分・操作不可は下記の業務系画面化対象。「OS 標準 UI はワイヤーフレーム化しない」節参照）
- 過去案件の参考デザインがある場合は、**網羅チェックの照合材料**として使う（コピー対象にはしない。古い・対象外の画面を含むことがあるため、要件を軸に取捨する）。
- **業務システムでは次の状態・画面も画面化対象に含める**（内容は仕様に従い、定義が無ければ画面化せず確認事項へ回す）：
  - **権限差分・操作不可**：操作できない場合は「なぜできないか・何をすれば可能か」を示す（disabled のまま放置しない）
  - **中断・復帰**：未保存変更がある離脱時の警告、一時保存の導線、セッション切れ後の復帰（長い入力・申請系で特に）
  - **業務プロセスの現在地**：今どのステータスか・次に何が起きるか・差戻し時どこを直すか（承認待ち／差戻し／完了／却下 等）
  - **業務例外・競合・失敗**：締切後/承認後の不可、他者更新済み、削除済み、連携失敗、在庫/枠不足 等も該当画面の文脈で画面化し、原因と復帰導線を示す
  - **一括操作・複数選択**：選択件数/対象の明示、一括実行前の確認、部分失敗の結果表示、全選択の範囲（現ページ/全件）、選択解除の導線を画面化する
  - **重要操作の事前明示・差分確認**：送信・申請・削除・重要な設定変更などは、実行前に影響範囲・条件・通知先・反映タイミング・変更/取消可否、必要に応じて変更前→変更後を確認できる画面を用意する（内容が仕様未定の場合は確定せず確認事項へ回す）

## ページ

- WF は **WF 正本ページ（役割：Wireframe。例名 `01_Wireframe` / `Wireframe`）** に置く。デザインは別の **Design ページ（例 `02_Design` / `Pages`）** に分ける（**WF 正本を直接デザイン化しない**）。
- 任意で、一覧識別用の **Cover**（例 `00_Cover` / `Cover`）や、遷移確認用の **Flow**（例 `00_Flow` / `Flow`）を置いてよい。
- ページ構成・命名の正本は `naming-conventions.md`「Page Naming」。案件に既存構成があればそれと整合させる。
- 凡例（Legend）は WF 正本ページ内の先頭付近に置く（詳細は「凡例（Legend）」節を参照）。

## 配色

- グレースケール基調（情報構造に集中させ、見た目の議論に逸れない）。
- 例外：危険・エラー・警告の**最重要シグナルのみ赤1色**で区別する（quality.md「ワイヤーフレームの配色」参照）。

## 凡例（Legend）— 必須

WF の先頭に凡例を必ず置く。レビュアー（クライアント / デザイナー / エンジニア）が記号を迷わず読めるようにする。最低限：

- 赤 = 警告・エラー・危険な状態
- 枠（プレースホルダ）= 画像 / メディア
- 濃グレー塗り = 主操作ボタン（Primary）
- アウトライン = 戻る / 副操作（Secondary）
- 選択中（ピル等）の表現

## キャプション（画面の説明）— 必須

各画面の「目的・主要挙動」を短く添える。

- **画面フレームの“外”（真下）に可視テキストで置く。** 常時読めてレビューしやすく、かつフレーム外なので **④デザイン昇格時に UI へ混入しない**（昇格するのは画面フレームのみ）。
- 画面フレームの**中**に補足・注記（`※ …` など）を書かない。説明はすべてフレーム外のキャプションに置く。フレーム内のテキストは UI の一部とみなされ、④デザインへ昇格したときに残ってしまう。
- フレーム内に置いてよいのは**実際の UI 文言だけ**（ラベル・ボタン・プレースホルダ・空状態メッセージ・状態表示の本文など）。
- **Figma の Annotation は、要素レベルの実装・挙動仕様（`Hover:` / `Sticky:` / `Breakpoint:` 等）と、機械可読な「要素↔注記」リンクとして積極活用する**（ノードに紐付き Dev Mode / API から参照でき、④デザイン昇格時にも UI へ混入しない）。記法は `handoff.md` / `naming-conventions.md` の Annotation Prefix に従う。
- **キャプションと Annotation は役割で分け、同じ事実を両方に書かない**（矛盾・ドリフトの元を断つ＝各情報は1箇所だけ）。**画面レベルの目的・挙動＝外部キャプション**（人間レビュー用）／**要素レベルの実装・挙動仕様＝Annotation**（実装・機械可読用）。片方で足りればそれだけでよい（両方必須ではない）。

## 状態・エラー

- 一覧ボードにまとめない。**該当画面の文脈**で見せる（画面にダイアログ / フォームを重ねた「状態画面」として、元画面のそばに配置）。
- 要件の受入条件（AC）・各機能の例外/エラーを網羅する。
- 状態画面のキャプションには「**どの画面で・どんな条件で出るか**」を書く（クライアント / PM / エンジニアが理解できる粒度）。

## OS 標準 UI はワイヤーフレーム化しない

OS が標準で提供する UI（位置情報・通知・カメラ等の**権限ダイアログ**、GPS / Bluetooth の**有効化を促すシステムダイアログ**など）は、アプリ側の画面として作らない（OS に委譲）。WF にはアプリが責務を持つ画面だけを置く。

- レビューで「画面の抜けでは？」と誤解されやすいので、**委譲する旨を該当画面のキャプションまたは Figma Annotation に明記**し、“意図して作らない決定”として残す。
- 例：位置情報の許可・GPS 有効化は OS 標準ダイアログに委譲し、アプリは「取得中」「取得失敗→継続確認」のみを扱う。

## 重要な状態分岐は別画面に分ける

成功 / 失敗、空 / データ有、権限差分など、**人が混同しやすい重要な分岐は同一画面に並置せず、別画面に分ける**。

> 例：結果画面で「正常」と「警告（赤強調）」のように出方が大きく異なる状態は、それぞれ別画面にする。1画面に複数状態を並べると、実際にどれが出るのか人間が誤解する。

## CRUD は実体で

追加 / 編集 / 削除は注記で済ませず、**実体の画面（モーダル等）**として用意する。

## 選択コントロール・展開状態

- **少数の択一（2〜3 択程度）**は、WF 段階で**フル幅のセグメント（横並びボタン）**として作る。配置・大きさは操作性に直結する**機能要素**なので、見た目調整（④）に回さず WF で確定する（タップ領域は ui-ux-principles.md 参照）。
- **選択肢が多い場合（4 択以上）**は横並びだと窮屈になるため、ドロップダウンや縦並びリストなど別の形にする。
- ドロップダウン等は、**展開した状態の画面**も 1 枚用意し、選択肢の見え方を共有する。
- 入力エラーは該当入力の**直下にインライン**で示す（どこで何を直すかを画面上で分かるように）。

## グルーピング

機能のまとまりごとに Figma の Section で束ねる（グループ名は案件に合わせる）。例：

- 共通（メインメニュー・アプリ情報 等）
- メインの業務フロー
- 履歴 / 一覧
- 設定・管理（マスタ）

> 状態・エラーは独立した束（セクション）にしない。各画面の状態は、その画面が属する束の中で「画面の下に状態帯を添える」形で見せる（上記「状態・エラー」参照）。

## レイアウト（余白・背景）

- Section の背景は、画面（白）と**差がつく薄グレー**にする（同色だと境界が分からない）。
- Section の余白は**上下左右すべて同じ値に揃える**（例：80px）。画面と画面の間隔も同じ値にする（下だけ空くなどの不揃いを作らない）。
- Section の幅・高さは**中身の範囲から算出する**（概算の固定値で指定しない。中身がはみ出す・余白が不均一になる原因）。隣り合う Section 同士も同じ余白で縦に並べる。
- ビューポート（標準の画面高さ）に収まらない画面は、固定高さで内容を切らず**中身に合わせて高さを伸ばす**（スクロール画面として表現）。フレーム内でレイアウト方向を変えた入れ物も高さ可変にすること（固定のままだと中身が切れる）。
- キャプションは**背景なし**のブロックで、画面フレームの真下に一定の間隔で置く（見出し太字＋説明文・行間150%程度）。
