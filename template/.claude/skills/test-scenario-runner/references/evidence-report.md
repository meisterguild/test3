# 確認結果レポート テンプレート

証跡ディレクトリ直下に `report.md` として作成する。証跡画像へのリンクはレポートからの相対パスで書く。

```markdown
# 動作確認結果レポート: <対象システム名>

## 実行情報

- 実行日時: <YYYY-MM-DD HH:MM>
- 対象仕様書: <パス（複数可）>
- シナリオファイル: <scenarios/<slug>.yaml へのパス>
- 確認対象: <全シナリオ / 指定ID>
- 環境: <ベースURLまたは対象アプリ / ブランチ / コミットハッシュ / ブラウザ・デバイス等>
- 確認方法: <使用した自動化手段。例: Playwright ライブラリによるブラウザ自動操作 + スクリーンショット目視確認>

## 結果サマリー

| 結果       | 件数 |
| ---------- | ---- |
| ✅ OK      | N    |
| ❌ NG      | N    |
| 🚧 BLOCKED | N    |
| ⏭️ SKIP    | N    |
| 合計       | N    |

## シナリオ別結果

| ID            | 画面         | タイトル                             | 結果  | 証跡                                                                    |
| ------------- | ------------ | ------------------------------------ | ----- | ----------------------------------------------------------------------- |
| ATT-LOGIN-004 | ログイン画面 | 認証成功時にダッシュボードへ遷移する | ✅ OK | [01](ATT-LOGIN-004_01_login.png) / [02](ATT-LOGIN-004_02_dashboard.png) |
| ...           |              |                                      |       |                                                                         |

## NG詳細

### ATT-XXX-NNN: <タイトル>

- **失敗した検証項目**: <expected のどれが満たされなかったか>
- **期待**: <仕様書・シナリオ上の期待値>
- **実際**: <観察された挙動（エラーメッセージ・表示内容など事実のみ）>
- **証跡**:

  ![NG時の画面](ATT-XXX-NNN_03_error.png)

- **原因切り分け**: <アプリの不具合 / シナリオ（仕様解釈）の不備 / 環境・データ要因> — <根拠>
- **備考**: <サーバログの該当箇所、再現手順の補足など>

## BLOCKED / SKIP の理由

| ID  | 結果       | 理由                 |
| --- | ---------- | -------------------- |
| ... | 🚧 BLOCKED | <前提条件・環境要因> |

## 動作確認の対象外（unmapped）

シナリオYAMLの `unmapped` を転記する。

| 仕様書内の位置 | 要件 | 対象外の理由 |
| -------------- | ---- | ------------ |
| ...            | ...  | ...          |

## 総評

<カバレッジ・NGの傾向・次のアクション提案（修正依頼・再確認など）>
```

## 記載ルール

- 「実際」欄には観察した事実のみを書く。推測（原因の仮説）は「原因切り分け」「備考」に分けて書く
- 証跡リンク切れを作らない — レポート作成後、参照している画像ファイルがすべて存在することを確認する
- NG が 0 件でも「NG詳細」セクションは「該当なし」と明記して残す（確認した証として）
