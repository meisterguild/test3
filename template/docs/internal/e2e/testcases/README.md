# E2E テストケース置き場

人間が自然言語で書く E2E テストケースの置き場。コードは書かない。
**e2e-qa-tester エージェント**（`.claude/agents/e2e-qa-tester.md`）がこのディレクトリのファイルを読み、Playwright CLI でブラウザを自動操作してテストを実施する。

## 使い方

1. `TEMPLATE.md` をコピーして `<機能slug>.md`（例: `login.md`、`cart.md`）を作成し、テストケースを書く
2. Claude Code に依頼する: 「`docs/internal/e2e/testcases/login.md` のテストケースを e2e-qa-tester で実行して」
3. エージェントが提示するテスト計画をレビューして承認する
4. 実行結果は `docs/deliverables/test-evidence/<slug>/<実行日時>/report.md` に残り、テストケースファイル内の各ケースの「実行結果」表にも判定と証跡リンクが書き戻される

## 書き方のポイント

- 1 ファイル = 1 機能・1 画面群。ケースはファイル内に見出しで並べる
- ケース ID は `TC-<機能>-<連番3桁>`（例: `TC-LOGIN-001`）で一意にする
- 手順は「何をどうするか」を1操作1行で書く。CSSセレクタ・要素IDなど実装詳細は書かない
- 定型操作（ログイン等）は `../flows/` に定義済みのフロー名で書くと、誰が書いても同じ操作が再現される（例: 「テストユーザーAでログインする（login-flow）」）
- 期待結果は判定可能な事実で書く（「〜が表示される」「〜に遷移する」）。文言まで固定したい場合は文言を明記する
