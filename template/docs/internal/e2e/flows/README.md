# 操作フローリファレンス

E2E テストで繰り返し使う定型操作（ログイン、カート投入、検索など）の手順書。
テストケースが「テストユーザーAでログインする（login-flow）」と書けば、e2e-qa-tester エージェントがここの手順を参照して実行する。**誰が書いたテストケースでも同じ操作が再現される**ようにするための単一の真実源。

## 運用ルール

- 1 ファイル = 1 操作単位（ログイン、カート投入など）。細かすぎる（1クリック）・粗すぎる（購入完了まで全部）は避ける
- ファイル名 = フロー名: `<操作>-flow.md`（例: `login-flow.md`）
- **自己改善**: e2e-qa-tester はテスト中に未定義の定型操作を実行したら、テスト完了後にその手順をここへ新規ファイルとして追記する。人が先回りして書いてもよい
- 手順は画面上の見た目（ラベル・ボタン名）で書く。snapshot の ref 番号や CSS セレクタは実行のたびに変わるので書かない
- 認証情報などの秘匿値は直接書かず、環境変数名や参照先を書く

## 書式

```markdown
# login-flow: ログイン

## 前提
- ログアウト状態でトップページを開いていること

## パラメータ
- ユーザー: テストユーザーA（認証情報は環境変数 TEST_USER_A_EMAIL / TEST_USER_A_PASSWORD）

## 手順
1. ヘッダーの「ログイン」リンクをクリックする
2. メールアドレス欄にユーザーのメールアドレスを入力する
3. パスワード欄にパスワードを入力する
4. 「ログインする」ボタンをクリックする

## 完了確認
- ヘッダーにユーザー名が表示される

## 備考
- 2回目以降は `state-save` / `state-load` でログイン状態を再利用してよい
```
