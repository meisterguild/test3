# 要件定義ドラフト: ブラウザで遊べるスイカゲーム

- 起点: [issue #1](https://github.com/meisterguild/test3/issues/1)（「ブラウザで遊べるスイカゲームを作りたい。まずは計画して、実装のIssueを作成して。」）
- ステータス: **ドラフト**（issue #1 の記述量が 2 行のため、以下は本ドラフト作成時点の推測を含む。確定版は
  `docs/deliverables/requirements-definition/` へ昇格させる）
- 位置づけ: 本ドラフトが実装 issue の**根拠 ID の真理ソース**。ゲームルールの詳細仕様は T-02（spec 起票）で
  `docs/specs/game-core-rules.md` として別途確定させる。

## 前提と推測の明示

issue #1 には「ブラウザで遊べるスイカゲーム」以外の指定がない。そのため以下を前提として設計した。
異議がある場合はここを起点に修正する（各 issue の根拠 ID から追跡できる）。

| # | 前提 | 理由 |
| --- | --- | --- |
| A-01 | 一般に知られる「スイカゲーム」型ルール（11 段階の果物進化・容器・デッドライン）を採用する | 「スイカゲーム」という固有名で依頼されているため、ジャンルの標準ルールが期待値と判断 |
| A-02 | シングルプレイ・オフライン完結。バックエンドを持たない | 「ブラウザで遊べる」以上の要求がなく、静的配信が最短で価値に到達する |
| A-03 | 日本語 UI 単一言語 | 依頼が日本語。多言語化の指示なし |
| A-04 | 商用配布しないため、果物のグラフィックは自前の図形描画（円 + ラベル）で表現する | 素材のライセンス調達を計画に含めない判断。差し替え可能な構造にする |

## 機能要件 (FR)

| ID | 要件 | 受け入れ観点 |
| --- | --- | --- |
| FR-01 | プレイヤーは落下位置を左右に指定し、任意のタイミングで果物をドロップできる | ポインタ移動 / タッチドラッグ / 矢印キーで狙いが動く。クリック / タップ / Space でドロップ |
| FR-02 | ドロップされた果物は重力・衝突・摩擦のある物理挙動で容器内に積み上がる | 果物が容器の壁と床を貫通しない。他の果物の上に乗って静止する |
| FR-03 | 同じ段階の果物どうしが接触すると、1 段階上の果物 1 個へ合体する | 合体後の果物は接触した 2 個の中点に生成される。2 個は消滅する |
| FR-04 | 最終段階（スイカ）どうしが接触した場合は両方が消滅し、最大スコアが加算される | スイカより上の段階は生成しない |
| FR-05 | 合体のたびにスコアが加算され、現在スコアが画面に表示される | スコアは合体後の果物の段階から決定論的に算出できる |
| FR-06 | ハイスコアがブラウザに永続化され、次回起動時にも表示される | `localStorage` に保存。保存値が壊れている / 読めない場合は 0 として扱い、例外を投げない |
| FR-07 | 果物がデッドラインを一定時間超えて留まるとゲームオーバーになる | ドロップ直後に線を通過するだけでは終了しない（猶予時間あり） |
| FR-08 | 次にドロップされる果物が事前に表示される | 出現対象は下位 5 段階からの抽選 |
| FR-09 | ゲームオーバー後にリスタートでき、プレイ中は一時停止 / 再開できる | リスタートで盤面・スコア・タイマーが初期化される |
| FR-10 | ドロップ直後は一定時間、次のドロップを受け付けない | 連打による多重ドロップが発生しない |
| FR-11 | 合体・ドロップ・ゲームオーバーに効果音が鳴り、ミュートを切り替えられる | ミュート状態も `localStorage` に永続化する。音源が読めなくてもゲームは継続する |

## UI 要件 (UI)

| ID | 要件 |
| --- | --- |
| UI-01 | ゲーム画面は「容器（プレイエリア）」「HUD（現在スコア / ハイスコア / 次の果物 / ミュート）」「デッドラインの視覚表示」で構成する |
| UI-02 | ゲームオーバー時にモーダルを表示し、最終スコア・ハイスコア・ハイスコア更新の有無・リトライ操作を提示する |
| UI-03 | スマートフォン縦持ち（375×667 相当）と PC（1280×800 相当）の双方で、スクロールなしにプレイエリア全体が収まる |

## データ要件 (DT)

| ID | 要件 |
| --- | --- |
| DT-01 | 果物定義テーブル（段階 / 表示名 / 半径 / 色 / 合体時スコア）を単一の定数として保持し、描画・物理・スコアの全てが同じ定義を参照する |
| DT-02 | ローカル保存データは「ハイスコア（数値）」「ミュート設定（真偽値）」のみ。個人情報は保存しない |

## 非機能要件 (NFR)

| ID | 要件 |
| --- | --- |
| NFR-01 | 果物 60 個程度が同時に存在する状態で、デスクトップ Chrome にて 60fps を目標とする（下限 30fps） |
| NFR-02 | 対応ブラウザは Chrome / Safari / Firefox / Edge の最新安定版。IE は非対応 |
| NFR-03 | 静的ホスティング（GitHub Pages）のみで動作し、サーバーサイド処理・外部 API 通信を持たない |
| NFR-04 | 合体判定・スコア計算・ゲームオーバー判定を単体テスト（Vitest）で、1 ゲームの通し操作を E2E テスト（Playwright）で検証する |
| NFR-05 | ゲームルール（合体・スコア・出現抽選）は物理エンジンに依存しない純関数として実装し、物理エンジンなしでテストできる |
| NFR-06 | 外部依存は物理エンジン等の必要最小限に留め、依存追加時は issue に理由を残す |

## 受け入れ条件 (AC) の候補

MVP 完了の判定に使う通しシナリオ。詳細は T-11（E2E テスト整備）で確定する。

- AC-01: 初回アクセスでゲーム画面が表示され、次の果物が見える（FR-08 / UI-01）
- AC-02: 狙いを左右に動かしてドロップすると、果物が落ちて容器内で静止する（FR-01 / FR-02）
- AC-03: 同種果物を接触させると 1 段階上へ合体し、スコアが増える（FR-03 / FR-05）
- AC-04: 容器を満杯にするとゲームオーバーモーダルが表示される（FR-07 / UI-02）
- AC-05: リロード後もハイスコアが保持されている（FR-06）
- AC-06: 375×667 の viewport でプレイエリア全体が収まり、タッチでプレイできる（UI-03）

## リスク (R)

| ID | リスク | 対応方針 |
| --- | --- | --- |
| R-01 | 同種果物の合体で、1 フレーム内に同じ果物が複数回合体してスコアが二重計上される | 合体済み果物を ID で即時マークし、物理ボディ削除は衝突処理後にまとめて行う（T-06 の DoD に含める） |
| R-02 | 物理パラメータ（反発・摩擦・重力）の調整不足で積み上がりが不自然になる | パラメータを 1 箇所の定数に集約し、調整を独立して行えるようにする（T-04） |
| R-03 | デッドライン判定が厳しすぎて、ドロップ直後に即ゲームオーバーになる | 「線を超えた状態が N 秒継続」で判定し、猶予時間を定数化する（T-08） |
| R-04 | モバイルでの canvas 解像度（devicePixelRatio）対応漏れで表示がぼやける | 論理サイズと物理サイズを分離し、DPR スケールを描画層で一括処理する（T-04 / T-10） |
| R-05 | 果物数の増加に伴うフレーム落ち | 静止した果物の sleeping を有効化し、NFR-01 を E2E で計測できる形にする（T-04） |

## 未確定事項（人間への確認事項）

以下は推測で進めており、後から覆る可能性がある。覆った場合は該当 issue を修正する。

- 果物のグラフィックを図形描画で済ませるか、イラスト素材を用意するか（A-04）
- ハイスコア以外の記録（プレイ回数・最大到達果物）を残すか
- 効果音の音源をどこから調達するか（自作 / フリー素材 / 無しで進めるか）
